# Миграция на файловое хранение чанков

## Что меняется

- Старые таблица `chunks` и её данные не удаляются.
- Новая схема создаёт `rag_documents` и `rag_chunks`.
- Текст чанков не сохраняется в отдельные файлы и не дублируется в PostgreSQL.
- В PostgreSQL хранятся путь к оригиналу, хеш, диапазон символов в извлечённом
  тексте документа, метаданные и вектор pgvector.
- При показе результата приложение повторно читает исходный TXT/код/PDF/DOCX
  или выполняет OCR изображения, затем берёт нужный диапазон текста. Содержимое
  одного документа может временно кэшироваться только в оперативной памяти.
- Повторная индексация неизменившегося файла пропускается, если векторная
  модель совпадает и у документа уже есть индекс.

## Перед запуском

1. Сделайте резервную копию базы PostgreSQL.
2. Сделайте резервную копию проекта.
3. Установите зависимости из `requirements-rag.txt`.
4. При обновлении с версии, которая копировала тексты чанков в `.rag_cache/chunks/`,
   один раз переиндексируйте документы. После успешной переиндексации старую папку
   `.rag_cache/chunks/` можно удалить: новая версия её не использует.
5. Для OCR изображений установите Tesseract OCR в ОС и проверьте, что `tesseract`
   доступен в PATH. Загрузчик OCR сейчас настроен на языки `rus+eng`.
5. Запустите приложение как обычно. `initialize_database()` создаст новые таблицы.

## Проверка

1. Выберите небольшую папку только с TXT/Python файлами.
2. Нажмите «Разбить на чанки».
3. Проверьте поиск и открытие текста найденного чанка.
4. Проверьте, что повторная индексация неизменённых файлов пропускается.
5. Проверьте небольшой PDF с выделяемым текстом и DOCX.
6. Для изображения с текстом проверьте OCR при установленном Tesseract.
7. Убедитесь, что `.rag_cache` не попадает в индексируемую папку. Загрузчик
   исключает каталог с именем `.rag_cache`.

## Ограничения первой версии

- Сканированные PDF пока не проходят OCR автоматически; PDF без текстового слоя
  сообщит понятную ошибку. OCR PDF можно добавить следующим этапом.
- Изображения индексируются по OCR-тексту. Для изображений без текста нужен
  vision-анализ или мультимодальная embedding-модель.
- Для DOCX индексируются абзацы и строки таблиц; колонтитулы, комментарии и
  встроенные изображения пока не обрабатываются.
- Векторный индекс HNSW намеренно не создаётся автоматически, поскольку
  размерность может отличаться у разных embedding-моделей. Пока поиск выполняется
  точным сравнением. После фиксации одной модели и размерности можно добавить
  HNSW индекс.
- При изменении embedding-модели файлы будут переиндексироваться по мере запуска
  обработки папки. Для чистого переключения модели рекомендуется повторно
  проиндексировать всю папку.

## Важно про удаление данных

Кнопка очистки в интерфейсе удаляет только `rag_documents` и `rag_chunks`.
Старая таблица `chunks` сохраняется. Файловый кэш не удаляется автоматически,
поскольку безопаснее сначала подтвердить, что база больше на него не ссылается.
После проверки кэш можно удалить вручную, когда приложение закрыто.
