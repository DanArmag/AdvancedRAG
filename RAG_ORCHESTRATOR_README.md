# Первый этап автоматического RAG

## Что добавлено

- `services/rag_orchestrator.py` — единый цикл маршрутизации, поиска, оценки и генерации ответа.
- `api/lm_studio.py` — метод `complete_chat()` для запросов без потоковой передачи, включая JSON-режим.
- `ui/app.py` — вместо прямой генерации вызывает оркестратор в рабочем потоке и показывает диагностические сведения в чате.

## Алгоритм

1. Маршрутизатор определяет, нужен ли поиск по локальным документам.
2. Если RAG не нужен, ответ формируется по обычной истории диалога.
3. Если RAG нужен, выполняется векторный поиск (первично 5 чанков).
4. Оценщик оценивает релевантность, полноту и достаточность найденных фрагментов.
5. При решении `retry` выполняется одна повторная попытка поиска (до 8 дополнительных результатов); результаты объединяются и ограничиваются 10 наиболее похожими чанками.
6. Модель отвечает с маркерами источников `[S1]`, `[S2]` и списком файлов/чанков. Если доказательств мало, она должна обозначить ограничения.

## Как читать диагностику

- **Релевантность** — насколько найденные фрагменты относятся к вопросу.
- **Полнота** — насколько они покрывают вопрос.
- **Достаточность** — можно ли дать обоснованный ответ по этим данным.

Это оценки LLM, а не объективные вероятности. Их нужно калибровать на тестовых вопросах с известными правильными источниками. `similarity` из pgvector не равна вероятности правильного ответа.

## Ограничения этой итерации

- Ответ выводится целиком, не потоково.
- Оценка качества выполняется той же LLM, которая генерирует ответ; это удобно для первого прототипа, но не является независимой оценкой.
- При ошибке маршрутизатора система пытается ответить без RAG и показывает причину в диагностике.
- Повторный поиск выполняется максимум один раз.
- Требуются доступные в LM Studio LLM и embedding-модель, а также рабочая PostgreSQL/pgvector и уже проиндексированные документы.
- Список источников показывает использованные для контекста результаты, а не доказывает, что модель использовала каждый из них.

## Проверка после обновления

1. Запусти обычное приветствие: маршрутизатор должен выбрать ответ без RAG.
2. Спроси о конкретном файле или реализации в своих документах: должен включиться поиск.
3. Убедись, что в чате видны запрос, количество результатов, оценки и решение оценщика.
4. Проверь, что ответ содержит ссылки `[S1]` и список источников.
5. Задай вопрос, которого нет в документах: система должна обозначить нехватку доказательств, а не придумывать содержимое файлов.

Если LM Studio/модель не поддерживает `response_format`, оркестратор повторяет JSON-запрос без этого параметра.
